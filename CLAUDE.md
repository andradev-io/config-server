# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Status

Early "config server" (README is just the title). Working pieces: `ConfigMerger`, JSON/YAML/.env formats, `GET /config/{application}/{environment}`, a files-management API, a Git-backed `IConfigSource` (`GitConfigSource`), pluggable authentication (any OIDC provider + scoped API keys), grant management driving the IdP admin API (`api/access`, Keycloak first), and a Vue 3 + Vuetify viewer in `src/Web`. Not wired yet: the Api registers a filesystem placeholder source, not the Git one. Not implemented: SOPS/secret resolution.

## Intent and design decisions

Source: Obsidian note "Configuration Hub" (outside repo). Server holds one default JSON config plus per-environment partial overrides (only changed fields); a client asks for an environment and gets default merged with that override. Replaces manual per-environment variable substitution in CI/CD releases. Git storage is an inference from `Git.cs`/`config-server-files`, not stated in the note.

Secrets (planned, not implemented):
- Use SOPS (age key, or a cloud KMS) to encrypt only sensitive values in the config files; server decrypts when building the response.
- Keep resolution behind an `ISecretResolver` extension point so a secret manager (Key Vault, Vault, etc.) can be added later with `secret://...` references, without changing file format.
- Never put plaintext secrets in overrides. Responses carrying resolved secrets require authentication and TLS (authentication exists, see Auth below; TLS is up to the deployment).

## Architecture

- `src/Application/ConfigServer.Application.Api` — ASP.NET Core web host, classic `Program` + `Startup` style. Maps `/health`, `ConfigController` and `FilesController`. `GET config/{application}/{environment}?format=json|yaml|env` (default json): merges default + override from `IConfigSource` (any mix of .json/.yaml/.yml/.env) and renders to the requested format (application/json, application/yaml, text/plain); 404 if no default OR no override (strict: no silent fallback), 400 on bad names, unknown format or invalid content (`{error,line,column}`). `FilesController` (`api/apps`): `GET /`, `GET {app}/files`, `GET|PUT|DELETE {app}/files/{fileName}` backed by `IConfigStore`; PUT/DELETE need `ConfigSource:AllowWrite=true` (403 otherwise; true in Development), 501 when the active source has no `IConfigStore` (Git), 409 on same logical name with another extension or deleting `default.*` while overrides exist; PUT validates content by parsing it (400 `{error,line,column}`) and writes UTF-8 no BOM, LF. Reserved `_*` files (`_environments.json` at the source root, `{app}/_variables.json`) are refused by the files API (400), hidden from `GET {app}/files` and never read as overrides. Management endpoints (`EnvironmentsController`, `VariablesController`, base `ConfigApiControllerBase`; reads need `IConfigCatalog` else 501, writes also need AllowWrite (403) and `IConfigStore` (501)): `GET|POST api/environments`, `PUT|DELETE api/environments/{name}[?deleteFiles]` (declared registry + environments inferred from override file names; POST may scaffold `{name}.json` per app), `GET|PUT api/apps/{app}/variables` (declared variables, validated), `GET api/apps/{app}/status` (required/type/secret-in-plain-text checks per environment), `GET api/variables[?search&app&env&declaredOnly]` => `{variables,warnings}` and `GET api/variables/{*key}` (cross-project index with `byEnvironment` defined|inherited|missing). Values are never returned by them. These endpoints expose configs and their structure: require authentication + TLS before non-local use. `OverridesController` (Azure DevOps-style variables grid): `GET api/apps/{app}/overrides` => `{app,etag,scopes:[default,...envs],variables:[{key,type,secret,declared,values{scope:{value,format,file}|{masked,file}},effective{env:{value,from}|{masked,from}}}],warnings}` (secrets masked, never returned); `PUT api/apps/{app}/overrides?dryRun=` body `{changes:[{key,scope,value?,remove?}],ifMatch?}` applies all changes atomically per request (400 `{error,key,scope}` writes nothing, 409 on etag mismatch, per-app in-process lock; dryRun skips the 403/501 write gate), writes each file in its own format via `ConfigFormat.Render` (comments are lost: warned), new scope files copy the default's format. Domain logic: `ConfigTree.TrySet/Remove` (prunes empty parents), `OverridesGrid`, `OverridesEditor`, `CommentDetector` in `Management/Overrides.cs`. All responses carry `Cache-Control: no-store`. `AddConfigSource` (in `Configuration/`) is the single place to swap the filesystem source (`ConfigSource:Path`, also registers `IConfigStore`) for `AddGitConfigSource`. CORS origins come from `Cors:AllowedOrigins` (GET, POST, PUT, DELETE; headers Content-Type, Authorization, X-Api-Key; Development allows `http://localhost:5173`). API tests are in `src/ConfigServer.Tests.Api` (`WebApplicationFactory` with a temp-directory source, plus a fake `IConfigSource`; `AuthTestHost` = Mode Oidc with a local HMAC signing key injected via `Configure<JwtBearerOptions>` (static OIDC config, no network) + `InMemoryApiKeyStore`).
  - Auth (`Authentication/`, registered by `AddConfigServerAuth` in Startup): `Auth:Mode` = `Oidc` (appsettings.json default) | `None` (appsettings.Development.json; every request is global admin "local"; any other environment fails startup). `Auth:Oidc`: `Authority` (required, https unless `RequireHttpsMetadata=false`), `Audience` (falls back to `ClientId`; one is required), `ClientId` (for the SPA), `Scopes` (default openid, profile; not in appsettings.json because arrays merge by index), `RoleClaim` (default `roles`; dotted path, or several separated by `,` = union; `{clientId}` (ignore case) is replaced by `ClientId`, required when used, e.g. Keycloak `roles,realm_access.roles,resource_access.{clientId}.roles`; resolved list in `OidcAuthOptions.RoleClaimPaths`), `RoleMap` (external role => config role string(s), comma list, keys case-insensitive, validated with the role parser; scoped admin is a startup error). Options are validated in `AuthOptions.Validate` (InvalidOperationException at startup). JwtBearer with `MapInboundClaims=false`; `OnTokenValidated` strips `urn:config-server:*` claims from the token (ignore case: claim lookups and claim policies are case-insensitive) and adds grant + coarse role claims.
  - `Auth:Oidc:MetadataAddress` (optional, absolute URL, https unless `RequireHttpsMetadata=false`) = JwtBearer `MetadataAddress`: fetch discovery/JWKS from an internal URL while `Authority` stays the public issuer tokens carry; the document's own `issuer`/`jwks_uri` are used as published. `ForwardedHeaders` (`Configuration/ForwardedHeadersExtensions.cs`, first middleware, off by default): `Enabled`, `KnownProxies` (IPs), `KnownNetworks` (CIDRs, e.g. `10.42.0.0/16`), `TrustAllProxies` (clears both lists; only when the API is reachable solely through the proxy, e.g. in-cluster nginx with no other ingress), `ForwardLimit` (default 1, 0 = all); reads X-Forwarded-For/Proto/Host.
  - RBAC, IdP-controlled (the server only reads roles from the token): role strings `config:<read|write|admin>[:<app>[:<env>]]`, app/env = name or `*`, omitted = `*` (`config:read` = everything, `config:write:billing-service` = all envs of that app, `config:read:billing-service:prd`). Prefix/permission ignore case; app/env names case-sensitive and validated with `ConfigNames` (no extra `:`); write ⊃ read; `admin` is global only (app-scoped admin ignored with a logged warning) and required for `api/keys`; invalid/unknown roles ignored. `ConfigPrincipal` stores each grant as claim `urn:config-server:grant` (`config:{perm}:{app}:{env}`) plus coarse `urn:config-server:role` (each level held in at least one scope; admin only when global); `ConfigPrincipal.Grants(User)` reads them back into `AccessGrants` (Domain).
  - Schemes: default `ConfigServer` policy scheme forwards to `ApiKey` when `X-Api-Key` or `Authorization: ApiKey ...` is present (wins over Bearer), else `Bearer` (Oidc) or `None`. Coarse policies `config:read|write|admin` check the role claim (admin also rejects API-key principals); then the global MVC `AccessScopeFilter` enforces grants for users and API keys alike (permission = write when an `[Authorize(Policy=write)]` applies, else read; admin endpoints skipped): route `app`/`application` needs the permission on at least one env of the app, `environment` on (app, env), files `{env}.*` on (app, env), `default.*` is readable with read on any env of the app (it is part of every merged config; keeps the key contract) and writable only with write on (app, `*`). `[RequireScope(AllEnvironments)]` = (app, `*`) on PUT variables; `[RequireScope(Global)]` = (`*`, `*`) on environment POST/PUT/DELETE; `[RequireScope(AllEnvironments, ApiKeysOnly = true)]` on GET overrides, GET status, `api/variables*` (API keys keep their 403 there, users get filtered views). Overrides PUT checks every change scope (`default`/empty needs write on (app, `*`); one denied change = 403, nothing written). Listings filter: `api/apps` (apps with any grant), `api/environments` (readable override files per app + envs with any grant), `{app}/files` (default + readable envs), `{app}/status` (readable envs, checked on the full snapshot), `{app}/overrides` (readable env scopes; `default` scope/values only with read on (app, `*`); keys of hidden env files not listed; secrets masked), variable index/detail (`SnapshotAccess.Restrict`: readable apps, readable override files, `byEnvironment` limited). Controllers: class `[Authorize(Policy=read)]`, mutations `write`, `KeysController` admin; FallbackPolicy = read; `/health` and `GET api/auth/info` anonymous; `GET api/auth/me` => `{name,roles,via:none|oidc|apikey,grants:[{permission,app,environment}]}` (`*` = all). `JsonAuthorizationResultHandler` writes 401/403 as `{error}` (401 adds `WWW-Authenticate: ApiKey` next to Bearer); the filter writes 403 `{error}`. AllowWrite 403 / 501 behaviors are unchanged and apply after the access checks.
  - API keys produce grants through the same evaluator (`AccessGrants.FromApiKey`: apps × environments with `write` or `read`, never admin; environment names compare case-insensitively for keys only, their historical contract). JSON contract and scoping unchanged.
  - `AccessController` (`api/access`, admin policy, never API keys; `IdentityAdmin/`, registered by `AddConfigServerIdentityAdmin` in Startup, `IIdentityAdmin` via TryAdd so it is replaceable): manages grants in the IdP, which stays the source of truth (grant = client role `config:<perm>[:<app>[:<env>]]` of the config client mapped to a user/group, effective at the subject's next token refresh/sign-in). `GET info` => `{provider:none|keycloak,enabled,configClientId,note}`; when disabled every other endpoint is 501 `{error}` (checked before validation). `GET users|groups?search&first(>=0)&max(1-100, default 20)` => `[{id,username,displayName,email}]` / `[{id,name,path}]`; `GET subjects/{user|group}/{id}/grants` => `[{permission,app,environment,role,inherited,via?}]` (`via` omitted when direct); `POST` same route `{permission,app?,environment?}` (default `*`) => 201 SubjectGrant, idempotent, named app/env must exist in the catalog with exact case (hint on case mismatch; skipped without `IConfigCatalog`); `DELETE ...?permission&app&environment` => 204 idempotent, syntax-only (stale names revocable). `IdentityAdminException` kinds: NotFound 404, Invalid 400, NotConfigured 501, Unauthorized/Denied/Misconfigured/Unavailable 502. Grants/revokes logged at Information (actor, subject, role). Options `IdentityAdmin` (`IdentityAdminOptions`, validated at startup): `Provider` None (default)|Keycloak; `Keycloak:BaseUrl` (https unless loopback or `RequireHttps=false`), `Realm`, `AdminClientId`, `AdminClientSecret` (env/secret store only, never logged or returned), `ConfigClientId` (default `Auth:Oidc:ClientId`), `TimeoutSeconds` (15). `KeycloakIdentityAdmin` (typed HttpClient, logged header values redacted; `KeycloakAdminCache` singleton = client_credentials token until 30 s before expiry, refreshed once on 401, plus the config client's internal id): role names URL-escaped as one path segment; grant = read direct mappings (404 => subject not found, nothing created) -> existing mapping parsing to the same grant is returned -> GET role (404 => POST create, 409 tolerated) -> POST mapping; revoke unmaps every direct role parsing to the grant and keeps the roles; user grants add group and parent-group (`parentId` walk) mappings as inherited; Keycloak 403 => message naming the missing realm-management role. Setup steps: `docs/keycloak-setup.md`. Tests: `KeycloakIdentityAdminTests` (`FakeKeycloak` handler), `AccessApiTests` (`FakeIdentityAdmin` through `AuthTestHost`'s `configureServices`).

- `src/Domain/ConfigServer.Domain` — library, referenced by the Api and Tests projects.
  - `Configuration/IConfigSource` — where config files come from (`GetDefaultAsync`, `GetOverrideAsync`); returns `ConfigDocument(Content, Format)` or null when missing. Lookup order per name: `.json`, `.yaml`, `.yml`, `.env` (first wins); files are `default.*` and `{env}.*`. `Git/GitConfigSource` implements it with LibGit2Sharp (clone, throttled fetch+reset by `RefreshInterval`; layout `{app}/default.*`; rejects `..`, `/`, `\` in names) and has no `IConfigStore` yet. `IConfigStore` (list apps/files, read, write, delete, `WriteReservedAsync`) is the files-management contract, implemented by the Api filesystem source; `IConfigCatalog` (list apps/files, raw read, `ReadReservedAsync`) is the read-side enumeration implemented by both the filesystem and Git sources; `ConfigNames` holds the app/file name rules. `ISecretResolver` (pass-through default) is the hook for SOPS.
  - `Configuration/Formats` — `ConfigFormat` (Json, Yaml, Env) with `Parse` (to a `JsonNode` tree) and `Render` (from a tree), detection from extension, `ConfigFormatException` (Message, Line, Column). YAML via YamlDotNet (typed scalars, anchors, `<<`); `.env` is hand-written (`KEY=value`, comments, `export`, quotes, `__` nesting; `KEY__0..n` become arrays; values are strings).
  - `Configuration/ConfigMerger` — core feature. `MergeTrees` deep-merges trees (objects recursively; arrays and scalars replaced; later wins); `MergeDocuments` parses mixed formats and renders any; `Merge(baseJson, params overrideJsons)` is the JSON-text wrapper (null/blank overrides skipped, throws `JsonException`).
  - `Http/RequestFactory.Build<TEntity>(RequestConfiguration, ...)` is the public entry. It builds a private `ServiceCollection` per call, registers a named `HttpClient` plus a Polly retry policy in a policy registry, builds a throwaway `ServiceProvider`, resolves `IHttpClientFactory`, and returns an `IHttpMethod<TEntity>`.
  - `Http/Request` (internal) does the work: switches on `RequestConfiguration.HttpMethod` ("GET"/"POST"; anything else returns `null`) to `HttpRequestGet` / `HttpRequestPost<T>`. Retry policy retries on any exception or non-success status; pass `IHttpRequestRetryHandler` to hook `OnRetry`.

  - `Security/` — `AccessGrants` (the one authorization evaluator: `ParseRole` => `RoleParseStatus` Valid|NotConfigRole|Invalid|ScopedAdmin, `FromRoles`, `FromApiKey`, `Can(permission, app, env)` with `*` = all (only a wildcard grant covers `*`), `CanAnyEnvironment`, `CanAllEnvironments`, `CanAnyApp`, `HasAny`, `HasGlobal`, `CanReadDefault`/`CanWriteDefault`, `AllowedApps`, `AllowedEnvironments`, coarse `Roles`; grants normalized: deduped, covered ones dropped, admin only global), `AccessGrant` record (`ToRole()` canonical string), `AccessPermission` Read<Write<Admin. `ConfigRoles` (global names, `Prefix`, `Expand` hierarchy). `RoleClaimResolver.ResolvePaths(roleClaim, clientId)`, `Extract(claims, path|paths)` (union over `,` separated paths; per path: exact claim type first, e.g. `https://x/roles`; else longest claim-type prefix holding a JSON object walked by the rest, keys with dots matched greedily, e.g. `realm_access.roles`, `resource_access.config-web.roles`; arrays => one role each, a single string => split on whitespace, a repeated claim type => values whole), `MapToRoleStrings` (`config:*` strings pass through, then `RoleMap` targets) and legacy `MapToConfigRoles` (global roles only). `Configuration/Management/SnapshotAccess` restricts snapshots to readable apps/override files; `VariableIndex.GetDetail(snapshot, key, isVisible)` filters the matrix.

  - `Security/ApiKeys/` — `ApiKey` record (Id, Name, Prefix, Hash, Apps/Environments with `*`, Permission read|write, CreatedAt, ExpiresAt?, RevokedAt?, LastUsedAt?; `StatusAt`, `AllowsApp` ordinal, `AllowsEnvironment` ignore-case). `ApiKeyToken`: `cfs_{8 chars a-z0-9}_{32 random bytes base64url}`, hash `sha256:{hex}` of the whole key, `Verify` with `FixedTimeEquals`. `ApiKeyManager` (create/rotate/revoke/authenticate, `TimeProvider`; LastUsedAt written at most once per minute per key, best effort). `IApiKeyStore` (list/get/find by prefix/add/atomic `UpdateAsync(id, Func<ApiKey,ApiKey>)`), `InMemoryApiKeyStore`, `JsonFileApiKeyStore` (temp file + rename, in-process lock, reload on mtime/size change, 0600 on Unix, fails closed on bad JSON). Api registers the file store at `ApiKeys:StorePath` (default `data/api-keys.json`, relative to the content root, git-ignored in the Api project) with `TryAdd`, so another store can be registered first.

## Gotchas

- `RequestFactory.Build<T>` accepts `ILogger`, but non-generic `Build(...)` overload doesn't forward it.
- `Request.Build` casts `HttpRequestGet` with `as IHttpMethod<TEntity>`, so GET only works when `TEntity` matches what `HttpRequestGet` implements (likely `string`); otherwise returns `null`.
- `GitTests.cs` once held a real-looking GitHub token (still in git history). Treat as leaked: revoke it; use placeholders in tests.
- Production/Docker now fail at startup until `Auth:Oidc:Authority` and `Audience`/`ClientId` are set (appsettings.json is Mode Oidc with empty values). `WebApplicationFactory` runs as Development, so tests default to Mode None.
- `ApiKeys:StorePath` must be outside `ConfigSource:Path` and the Git `LocalPath` (startup throws); in Docker mount a volume for `/app/data`. The JSON file store assumes one server process per file.
- `RoleMap` keys are configuration keys: case-insensitive and cannot contain `:` (values can: scoped role strings). A single-string role claim is split on spaces, so a one-element array holding a role with spaces is split too. `RoleClaim` uses `,` as a path separator, so a claim name containing a comma cannot be addressed.
- Role app/env names are case-sensitive (`config:read:web:prod` does not open `config/web/PROD`) while the catalog and API keys treat environment names case-insensitively; a registry entry `Prod` needs the role to say `Prod`.
- `api/auth/me` `roles` lists levels held in at least one scope, so a user with only `config:write:billing-service:dev` gets `config:write`; use `grants` to decide per app/env.
- `api/access` changes reach a user only at the next token refresh/sign-in. Revoking on a user leaves group-inherited grants. Keycloak 23+ lists only top-level groups without a search; parent-group inheritance relies on `parentId` in Keycloak's group JSON (23+); composite roles are not shown. The Keycloak client is tested against a fake handler only.
- Demo: a 413 caused by a cap can leave a multi-file write (Overrides PUT) partly applied; the sandbox rate limiter keys anonymous callers on `RemoteIpAddress`, so behind a proxy without `ForwardedHeaders` they all share one bucket; DemoIdentityAdmin state and the per-workspace caches live in memory (lost on restart, one process assumed).
- API keys never get `config:admin`; `api/keys` is reachable only by an OIDC global admin (or Mode None). In Mode None an API key header still authenticates as that key (scoped), and a bad key is 401.
